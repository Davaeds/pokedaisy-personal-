change to any of the places listed under "Where it's decided" updates its rows here in the same commit.

## What each column is

- **EXPAND**: ASPECT > EXPAND, the overworld rebuilt past the GBA's edges (`pk_wide.c`).
- **Battle buttons**: the BATTLE tab's FIGHT / BAG / POKéMON / RUN and the move buttons press the game's own menus
  (`BattleInputController`). Without them the battle panes are information only.
- **One-press picks**: a FIGHT / move tap writes the menu's cursor and presses A once (GitHub #33). Without it a tap
  walks the cursor blind, 46-90 frames a tap (the "taps take a while" report).
- **POKéMON switch**: the battle POKéMON pane switches the tapped party slot in (the closed loop on gPartyMenu, or on
  a Game Boy game's own party menu).
- **Field items**: ITEMS' USE (Repels, medicine, PP items) and GIVE / TAKE on a Pokémon (`FieldItems.kt`).
- **FLY**: the MAP tab's FLY button (`Fly.kt`).
- **Trainer card**: the CARD tab (`TrainerCard.kt`).
- **Field reads**: SCENE SPEEDS' TEXT SPEED, CONTROLS > AUTO-RUN and RUN INDOORS (`pk_field_state`). BATTLE / MENU
  SPEED and GUIDE > HERE's caught count need no per-ROM table: every game.
- **Bike / surf**: SCENE SPEEDS' BIKE / SURF SPEED, from the game's own player state (and AUTO-RUN's bike check).
- **Wild encounters**: CONTROLS > WILD ENCOUNTERS (`WildEncounters.kt`).
- **PC anywhere**: the BAG's `PC` button (`Pc.kt`).

## Where it's decided

- **EXPAND**: `app/src/main/cpp/pk_wide_games.h`, generated by `scripts/gen_wide_tables.py` (retail by SHA-1, the
  hacks in its `HACKS`; `pending` ones only in `verify_wide.py`'s build). Check with `scripts/verify_wide.py`.
- **Battle buttons**: `NativeConfig.hasBattleInputAddrs` (gBattlerControllerFuncs + the action / move input
  handlers). Ruby / Sapphire: pokeruby's ELFs (its static controller functions, the same in both games and in rev 2),
  the other languages mapped by `port_retail.py` (Japanese R / S's HandleInputChooseMove read off the game headless,
  its `HEADLESS` table) and checked by `verify_ports.py` (action, FIGHT, BAG and POKéMON handlers on every port). One-press
  picks walked and written headless on English Sapphire rev 1 (`sapphire_rev1_battle`), German Sapphire rev 1 and
  Japanese Sapphire rev 1; the other ports' cursors are mapped through the literal pools (English's RAM in the Western
  ones). No POKéMON switch there: R / S's party menu keeps its cursor in a sprite's data, not in a gPartyMenu.
- **One-press picks**: `NativeConfig.actionCursor` / `moveCursor`, handed out only for a hash-verified ROM
  (`TelemetrySampler.knownCursorAddrs`). Configs made with `.copy()` inherit them: zero them where the RAM moved.
- **POKéMON switch**: `PokeDaisyActivity.switchAddrsFor` (by `GameKind`, game code and revision), or
  `NativeConfig.partyMenu` for the games it reads from their config (SoulGold, Recharged Yellow, Recharged Emerald, Super
  Mariomon, the FireRed / LeafGreen ports); the Game Boy games through `TelemetrySampler.gbPartySwitch` (Yellow in every
  language, the Crystal family), with their addresses on `Gen1Config` / `Gen2Config` (`partyMenuType` /
  `playerMonNumber`, `partyMenuAction` / `curBattleMon`).
- **Field items**: `fieldItemsForGame` in `FieldItems.kt` (retail tables + `FieldItemsPortsGen.kt`), or the config's
  own `NativeConfig.fieldItems` for a rebuild that shares retail's game code (Recharged Emerald:
  `FieldItemsRechargedEmeraldGen.kt` from `scripts/find_field_items_recharged_emerald.py`), each gated on its
  functions' code CRCs at run time.
- **FLY**: `FieldItemFns.fly`: the English FireRed rev 1, LeafGreen and Emerald tables, `FieldItemsPortsGen.kt`'s
  (`scripts/port_field_items.py`, FireRed rev 0 from rev 1) and the hacks using FireRed rev 0's (the 16-bit map
  section ones through `GET_MAPSEC_TYPE_U16`). Flown headless (party slot 0 given the move with SetMonData, the
  badge flags set where the save hadn't them) on English FireRed rev 0, LeafGreen rev 0 / 1, Japanese FireRed /
  LeafGreen, Spanish / French / German / Italian Emerald, Radical Red, Ultra Violet, Gaia, Amethyst, Sword and
  Shield and Orange Islands, Ruby rev 1 / 2, Sapphire rev 1 / 2, German Ruby, French Sapphire and Glazed. Ruby /
  Sapphire: `FLY_RUBY` / `FLY_SAPPHIRE` (Emerald's heal warp, their static map-type function, the map-type check with
  gMapHeader in place of SetUpFieldMove_Fly, gLastFieldPokeMenuOpened), the other languages ported from Ruby rev 1.
  Unbound: `flyUnbound` - CFRU's own GetMapsecType / SetFlyWarpDestination (their jump stubs' CRCs), the towns from
  its list of fly spots, sRegionMap pinned for the warp (`RegionMapPin`); flown headless to Frozen Heights and another
  spot. Not Kaizo, Celia (its VarGet isn't found, so no field-item table at all) or the other expansion builds. Heart and Soul, Lazarus
  and Emerald Imperium (pokeemerald-expansion, gcc - nothing maps from retail): `FIELD_ITEMS_HEART_AND_SOUL` /
  `_LAZARUS` / `_IMPERIUM`, FLY and PC only (`bagActions = false`; the Field items column stays —). Heart and Soul from its
  own source (2.0.6) built plain with Debian's gcc 12; Lazarus and Imperium from pokeemerald-expansion 1.10.0 built the
  same way - each function found by its masked first instructions or through its callers' BLs. The expansion renumbered
  MON_DATA (`FlyFns.monMoveField` / `monEggField`); Lazarus's town table is 122 rows (its towns from section 90); Heart
  and Soul's FLY gate is its gFieldMoveInfo entry's own functions. Flown headless on each, the PC opened on each. SoulGold (its four
  builds, `fieldItemsCandidatesForGame`: the code CRCs pick one): v1.1.4 from pokeemerald-expansion 1.13.0's build plus its
  own code (gFieldMoveInfo, SetFlyDestination's literal and calls, GetMapsecType's switch); the v1.2 builds from v1.1.4.
  Emerald Legacy (`FIELD_ITEMS_EMERALD_LEGACY`, `FLY_EMERALD_LEGACY`, `PC_EMERALD_LEGACY`): its source at V1.1.4 built with
  agbcc is the release byte for byte, so every address is its ELF's and every CRC its own code's (retail's functions,
  their calls moved; FLAG_BADGE06_GET 0x8CC). Flown headless four times in a row (Oldale, Littleroot, both twice: no
  reload trouble as on Kaizo), the PC opened and closed, a Potion used on a damaged Pokémon.
- **PC anywhere** (the BAG's `PC`): `FieldItemFns.pc` (`Pc.kt`): the retail tables, `FieldItemsPortsGen.kt`'s
  (`scripts/port_field_items.py` maps them, each entry checked against its gSpecials) and the hacks that use those
  tables; gated on ScriptContext_SetupScript / the PC special's CRCs and its gSpecials entry. Opened headless on
  Ruby rev 1, German Emerald, Japanese FireRed and Unbound.
- **Field reads**: every row of `pk_wide_games.h` with CONTROLS_LOCKED, `PK_WIDE_ROMS` and the pending hacks'
  `PK_FIELD_ONLY_ROMS` (`pk_field_knows`, `WideScreen.fieldGameFor`); RUN INDOORS not on Ruby / Sapphire. RUN INDOORS'
  gMapHeader bit was checked on retail FireRed / Emerald; the hacks are assumed to keep it.
- **Bike / surf**: `pk_wide.c`'s `playerAvatar`: gPlayerAvatar at gObjectEvents + 0x240 (R.O.W.E. + 0x4A8), checked
  live (objectEventId, gender, one movement flag) and kept once found; Ruby / Sapphire by the player's sprite ids.
  Probed headless on one save per game (FireRed, LeafGreen, Emerald with its German and Japanese releases, and every
  hack marked ✅); the other languages and versions are assumed to share it - the live check turns it off where not.
- **Wild encounters**: the games with field reads where `WildEncounters.find` finds the game's sWildEncountersDisabled by
  StandardWildEncounter's code: retail FireRed / LeafGreen / Emerald / Ruby / Sapphire in every language, the hacks that
  kept that code (Glazed, Kaizo, Gaia, Odyssey, Orange Islands, Ultra Violet, Celia, and Emerald Legacy's agbcc rebuild of
  Emerald's: OFF walked headless in Route 101's grass), the CFRU hacks (their own
  StandardWildEncounter reads FireRed's switch) and the gcc builds by a looser shape of the same check (`gccRead`:
  SoulGold, Lazarus, Recharged Yellow, Seaglass, Imperium, Too Many Types 2, Heart and Soul, R.O.W.E., Super Mariomon).
  Each gcc one walked headless: warped onto grass (Seaglass and Imperium on water) with the `warp` script command, OFF
  gave 180 steps without a battle, NORMAL one within 80 (SoulGold v1.1.4 and v1.2, Recharged Yellow v1.8.0 and v1.9.7,
  Mariomon v1.3 and v1.5.2). Not Emerald Rogue or Quetzal (their checks aren't found).
- **Trainer card**: `NativeConfig.trainerCard` (Emerald Legacy's: its own card style, `CardStyle.LEGACY`, for its fifth
  star's black card). SoulGold (every build), Lazarus and Recharged Yellow (every build) draw their own cards
  (`CardStyle.SOULGOLD` / `.LAZARUS` / `.RECHARGED_YELLOW`): their art found from headless VRAM dumps of the open card and
  each card's code, their save fields and star rules poked in and checked against the game's card. Each matched the
